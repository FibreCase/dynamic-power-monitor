# 任务调度与性能检查

本次检查覆盖 `main/` 固件、共享 I²C、PWM/NVS、HTTP/OTA、网页与构建配置。
结论基于源码、ESP-IDF 构建及硬件/RTOS 替身测试；尚未在实际 ESP32-C3 上测量延迟、栈余量或电流。

## 已修复的问题

| 问题 | 改动 | 影响 |
|---|---|---|
| 采样每 5ms 唤醒并获取锁，ECO 下大多数唤醒无有效工作 | 根据实际周期等待，超时不连续补采 | 正常时采样任务从约 200 次/秒降至 PWR 10 次/秒、ECO 1 次/秒；不包括其他任务和 RTOS tick |
| OLED 每 100ms 重发整个画面 | 缓存最后成功画面，仅变化时发送 | 静态画面不重复占用 I²C；界面仍每 100ms 检查变化 |
| OLED 传输失败后可能缓存部分画面 | 失败不缓存并强制下一次重发；同帧剩余块停止发送；增加缓冲区边界检查 | 防止错误画面被当作成功画面，也避免一个断线屏幕触发几十次连续超时 |
| NVS 写 Flash 时持有 PWM 读锁 | 写入串行锁与运行值快照锁分开 | GPIO 控制可读取上一次有效配置，提交成功后再更新运行值 |
| OLED/OTA 优先级高于输出控制，HTTP 默认优先级也较高 | 调整优先级；OTA 每个下载块主动让出 CPU | 采样、按键与输出控制优先于显示和大块写入 |
| WiFi/HTTP/环境调度在稳定状态持续短周期轮询 | 模式通知唤醒；异常才定时重试；环境按剩余采样周期等待 | 减少无效唤醒，模式变化仍能及时缩短环境采样间隔 |
| WiFi connect/start/stop 失败后可能不再重试 | 后台任务统一连接请求与失败重试；丢失 IP 时重新连接 | 网络事件处理不直接重复操作驱动，失败后继续恢复 |
| 电源模式与控制模式分开读取 | 在一个短临界区复制两者再计算输出 | 避免把新旧模式组合用于同一次 PWM 更新 |
| 普通 bool 跨任务读写 WiFi 状态 | 使用现有原子 ready/enabled 状态，删除重复标志 | 消除状态副本不一致和无锁读写 |
| 告警边沿读取三次 I²C，拖延按键和 PWM 任务 | 告警日志使用最近采样缓存 | 告警仍记录，但日志电压/电流/功率对应最近样本，不保证告警边沿的即时读数 |
| OLED/采样/状态任务创建结果未检查，且提前确认 OTA | 检查创建结果，全部任务创建成功后确认应用 | 内存不足不再静默缺少关键任务 |
| 短暂 ENS160 I²C 错误就重新初始化，可能反复预热 | 先重试读取，连续三次错误再初始化；明确设备状态错误仍重新初始化 | 减少短暂总线异常造成的预热重启 |

## 调度与资源选择

| 任务 | 优先级 | 等待方式 |
|---|---|---|
| INA226/电源模式 | 3 | PWR 100ms、ECO 1000ms，按周期等待 |
| 雷达/按键/PWM/LED | 3 | 50ms 周期等待，不执行 I²C |
| 环境传感器 | 2 | PWR 1000ms、ECO 10000ms；电源变化通知 |
| WiFi 生命周期 | 2 | 通知等待，失败连接/启停约 1 秒重试 |
| HTTP 生命周期 | 2 | 通知等待，失败约 1 秒重试 |
| HTTP 服务 | 2 | 服务器网络等待 |
| OLED | 1 | 100ms 检查，画面变化才传输 |
| OTA | 1 | 网络/Flash 操作，每个块至少让出一个 tick |

OLED 缓存额外使用 1024 字节静态 RAM。HTTP 服务栈从默认值增加到 6144 字节，为约 1.5KB 的本地 JSON/URL 缓冲及库调用留出空间；最多四个连接，启用 LRU 清理，接收/发送等待设为 2 秒。HTTP 停止依然可能等待当前连接处理完成，但不会阻塞采样任务。

两路 PWM 由 LEDC 硬件持续输出，仅占空比变化时更新。NVS 保存仍使用单条带版本记录，保持重复值不写入、提交失败不更新运行值的行为。

FreeRTOS tick 保持 1000Hz，本次没有启用 light sleep、调整 CPU 时钟或改变电压阈值；任务唤醒减少不等同于已测得功耗下降。Flash 擦写仍可能短暂阻塞 CPU/I²C，这是需要在板上测量的限制。

## 验证

```sh
python3 -m unittest discover -s tests -v
source /home/fibre/.espressif/v6.0.1/esp-idf/export.sh
idf.py -B /tmp/power-monitor-build build
```

七项主机回归测试直接运行选取的生产 C 例程，用驱动和 RTOS 替身检查：

- OLED 静态画面不重发，失败后包括画面回退都能恢复。
- OLED I²C 缓冲区边界与失败后剩余块短路。
- RA/BL/ON/OFF 在 PWR/ECO 下的占空比输出规则。
- NVS 提交期间不持有快照锁，失败、重复保存及加载行为。
- 采样周期、2 秒 Loading 门限与模式重置。
- WiFi 启停/连接失败重试与稳定状态阻塞。
- HTTP 模式启停、失败重试与服务器句柄管理。

构建通过，固件适合当前 1700KiB OTA 槽。替身测试不模拟实际 I²C 时间、WiFi 事件全部组合、Flash 停顿或任务栈使用。

## 上板验收

1. 确认 Loading 持续到启动完成后 2 秒，PWR/ECO 可反复切换且回到 RA。
2. 用逻辑分析仪观察 I²C：静态 OLED 不再每 100ms 重发，环境采样频率仍为 1Hz/0.1Hz。
3. 在 NVS 保存、OTA 下载和传感器断线期间，检查按钮响应、输出规则和看门狗。
4. 确认屏幕断线后恢复能重新显示完整画面；WiFi/AP 断开恢复后 HTTP 自动启停。
5. 测量各任务栈高水位、最小空闲堆、采样最大间隔及板上电流，再决定是否进一步降低 CPU 时钟或启用睡眠。
